### 两个必须先解决的问题

#### 问题 1：`.gitignore` 是一个"目录"，不是文件

```
Name: .gitignore    PSIsContainer: True    Attributes: Directory
```

git 只识别**文件**形式的 `.gitignore`。它现在是个空目录 →
**所有忽略规则全部失效**（同时也解释了为什么之前加规则"没效果"）。

#### 问题 2：仓库里躺着 3 个体积危险的文件

| 文件 | 大小 | 状态 | 风险 |
|---|---|---|---|
| `data/ub_labels.csv` | **94.51 MB** | 未跟踪 | `git add -A` 会把它加进去，逼近 GitHub 单文件 100MB 硬限制 |
| `output/legacy/预处理后的数据.csv` | **83.68 MB** | 未跟踪 | 同上；且是旧版中间产物，无入库价值 |
| `data/UserBehavior--1.csv` | 40.19 MB | **已被跟踪（已在历史里）** | 源数据，自首次提交起就在仓库里，`.gitignore` 管不住它 |

> **结论：在修好 `.gitignore` 之前，绝对不要执行 `git add -A` 或 `git add .`。**
> 这两个 80-94MB 的文件一旦进入暂存区，push 大概率被拒绝，且清理历史非常麻烦。

## 二、Step 1　修 `.gitignore`

```powershell
cd e:\aPythontest\Simple-Implementation-Project-for-an-E-commerce-Data-Warehouse

# 它是个空目录，先删掉
Remove-Item .gitignore -Recurse -Force

# 确认已删除（应为 False）
Test-Path .gitignore
```

然后**新建文件** `.gitignore`，内容如下：

```gitignore
cd e:\aPythontest\Simple-Implementation-Project-for-an-E-commerce-Data-Warehouse

$gitignore = @'
# ---- 源数据：体积大，可从原始渠道重新获取 ----

# ---- 运行产出：任何环境都能重新生成 ----
output/
pbix/

# ---- Python ----
__pycache__/
*.py[cod]

# ---- Office/WPS 临时锁文件 ----
~$*
*.tmp

# ---- 编辑器 / 系统 ----
.vscode/
.idea/
Thumbs.db
desktop.ini

# ---- 笔记：只上传交付物文档，其余（日志/学习总结/教程/草稿/简历）不上传 ----
# 注意：必须是 notes/*（不是 notes/），否则下面的 ! 放行会失效
notes/*
!notes/指标口径字典.md
!notes/操作手册_20260923_face修复与旧版归档.md
!notes/操作手册_20260924_face入口清洗.md
!notes/操作手册_20260924_Git提交与推送.md

[System.IO.File]::WriteAllText("$PWD\.gitignore", $gitignore, (New-Object System.Text.UTF8Encoding($false)))
```

**注意**：`.gitignore` 只对**尚未被跟踪**的文件生效。
`data/UserBehavior--1.csv` 已经在历史里，加规则**不会**让它消失（处理方式见 Step 2）。

## 三、Step 2　决定 40MB 源数据的去留

| 选项 | 命令 | 效果 | 建议 |
|---|---|---|---|
| A 保留现状 | 不操作 | 仓库继续背着 40MB 源数据 | 可接受 |
| B 停止跟踪 | `git rm --cached data/UserBehavior--1.csv` | 本地文件保留，后续提交不再包含；**历史里仍存在** | **推荐** |
| C 彻底清除历史 | `git filter-repo --path data/UserBehavior--1.csv --invert-paths` | 历史里也消失 | 会重写全部提交，风险高，现在不做 |

选 B 之后，`.gitignore` 里的 `data/*.csv` 就会生效，本地文件不受任何影响。

## 五、Step 4　建分支 + 暂存 + 提交

```powershell
# 分支命名：refactor/ 表示结构性改造
git switch -c refactor/dw-upgrade

# 先加"小文件"，逐个方向可控
git add .gitignore
git add README.md requirements.txt
git add src/ sql/ notes/
git add src/legacy/ output/legacy/
git add -A            # 记录旧链路文件的删除（main.py、src/ 顶层旧脚本等）
```

**`git add -A` 之前必须再复查一次**：

```powershell
git status --short
# 复查点：?? / A 开头的条目里，不应出现 data/*.csv、output/ 下的大文件、pbix/

git diff --cached --stat | Select-Object -Last 3
# 复查点：总插入量应该在"文本规模"，不是几百 MB
```

提交（PowerShell 不支持 bash 的 heredoc，用多个 `-m`，每段成为一个段落）：

```powershell
git commit -m "refactor: 单脚本版升级为五层数仓版，旧链路归档" -m "- 新增 sql/(ODS→DIM→DWD→DWS→ADS) 与 src/ 数仓版分析脚本，替代原 Pandas 单脚本链路" -m "- 旧链路（单脚本 + K-Means 三群）整体归档至 src/legacy/ 与 output/legacy/，并写 README 说明升级理由" -m "- face 脏值改为入口清洗（db_loader 导入时规范化），职业去重值 147→146" -m "- 新增 notes/：指标口径字典、操作手册、项目日志、学习总结" -m "- 修复 .gitignore（原为空目录，忽略规则一直未生效）"
```

## 七、Step 6　分支基础操作（本次要学的核心技能）

```powershell
git branch                        # 看本地分支
git branch -a                     # 看本地 + 远程分支
git log --oneline --graph --decorate -10   # 看图状历史

git switch main                   # 切回主干（默认分支名可能是 master，先 git branch 确认）
git merge refactor/dw-upgrade     # 把分支合进主干
git branch -d refactor/dw-upgrade # 合并后删除分支

git push origin main              # 推送主干
```

**要理解的三件事**：
1. **分支是一条可并行的提交线**：在分支上折腾不影响 `main`
2. **切分支时未提交的改动会跟着走**（所以先提交、再切分支更干净）
3. **`git switch` 是 `git checkout` 的现代写法**，切分支用它更不容易误操作

## 八、常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 中文路径乱码 | `git status` 显示 `\345\233\276...` | `git config --global core.quotepath false` |
| 大文件已进历史 | push 被拒 / 仓库暴涨 | 尽早 gitignore；已提交的需 `filter-repo` 重写历史，代价很大 |
| `.gitignore` 不生效 | 加了规则文件仍出现在 status | ①它是目录不是文件 ②该文件已被跟踪（需 `git rm --cached`）|
| WPS 锁文件 | `~$xxx.xlsx` 出现在 status | 关闭 WPS 后删除该文件 |
| 换行符告警 | `LF will be replaced by CRLF` | 可忽略；要统一可加 `.gitattributes` |
| `git add -A` 手滑 | 一次加进 94MB 文件 | `git rm --cached <文件>` 撤回跟踪 |
