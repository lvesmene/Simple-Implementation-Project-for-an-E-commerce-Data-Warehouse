## 二、必须先补的短板：现有复核样本"算不出召回率"

现状：`output/负面评论抽样复核表.csv` 共 20 条，**全部来自负面分数带**（`score < 0.2`）。

| 指标 | 现在能算吗 | 原因 |
|---|---|---|
| 负面**精确率** | 能 | 抽样池全是"模型判负面"的样本，19/20 真负面 → 约 95% |
| 负面**召回率** | **不能** | 需要"模型判正面/中性、但人工标真负面"的样本，现在一条都没有 |
| 整体 macro-F1 | **不能** | 样本里完全没有正面/中性样本 |

**结论：要让实验有意义，必须重建一份覆盖三个分数带的分层标注集。**

### 2.1 现有复核表的 4 个缺陷（重建时要一并修掉）

| 缺陷 | 后果 | 修法 |
|---|---|---|
| 缺 `(user_id, goods_id)` 唯一标识 | 无法回连原始数据、无法与模型预测逐条对齐 | 导出时保留标识列 |
| `comment` 被截断到 80 字 | 长评论语义不全，标注容易失真 | 保留全文 |
| 只有负面带 | 无正/中性样本，算不出召回率 | 三带分层抽样 |
| 被 WPS 存成 ANSI(GBK) | 脚本按 `utf-8-sig` 读会乱码 | 统一另存为"CSV UTF-8"或读取时用 `gb18030` |

> 因为这 4 点，现有的 20 条**无法回连、无法复用为标注集**，只能作为一次"负面带精确率约 95%"的试点结果记录在案。

## 三、数据设计

### 3.1 分层抽样（重建标注表）

| 分数带 | 抽样数 | 说明 |
|---|---|---|
| `[0.00, 0.20)` 负面带 | 40 | 最容易出现"误判为负面" |
| `[0.20, 0.80)` 中性带 | 40 | 阈值主要影响的区间，含大量模糊样本 |
| `[0.80, 1.00]` 正面带 | 40 | 提供正样本，才能算负面召回 |
| 合计 | **120** | |

### 3.2 标注规范（4 类标签）

| 标注值 | 含义 |
|---|---|
| 真负面 | 对商品 / 物流 / 售后有明确不满 |
| 真中性 | 中性描述、仅陈述事实、无明显情感 |
| 真正面 | 明确满意 |
| 模糊 | 反讽、转折句、脱离品类无法判断 → **不计入指标**，单独统计条数 |

**标注三条纪律**：
1. **只看 `comment` 原文**，绝不看 `score` 与 `label`（否则会被模型带偏 → 标注污染，实验失去意义）
2. 因此导出标注表时**不要带 `score` / `label` 列**，并随机打乱顺序（防止顺序泄露原分数带）
3. 每条保留 `(user_id, goods_id)` 作为唯一键，便于回连与对齐预测

### 3.3 分层抽样的副作用（必须在报告里声明）

分层抽样人为把三类比例做成约 1:1:1，而清洗后真实分布约为
**正面 5,720 : 中性 2,723 : 负面 5,521**（合计 13,964）。因此：

- **不要用 accuracy 当主指标**（会被抽样比例扭曲，得出乐观结论）
- 主指标用**每类的精确率 / 召回率 / F1 + macro-F1**
- 若要报整体准确率，需按真实先验加权，或另留一份"按真实比例随机抽样"的验证集

## 四、方法

### 4.1 对照组（Baseline）：SnowNLP 阈值法

直接复用 `src/sentiment_analyzer.py` 的现成结果与阈值 `[0.2, 0.8]` 三分法，
**保证与现行口径完全一致**，实验才有可比性。

### 4.2 实验组：TF-IDF + 逻辑回归

```
jieba 分词（复用 ECOMMERCE_WORDS + STOPWORDS）
  → TfidfVectorizer(ngram_range=(1, 2), min_df=2)
  → LogisticRegression(class_weight="balanced", max_iter=1000)
```

- `class_weight="balanced"`：应对类别不平衡
- `ngram_range=(1,2)`：捕捉"不好 用""不 推荐"这类**否定搭配**（SnowNLP 的薄弱点）
- **复用同一套分词与停用词**：让两组唯一的差异只剩"分类器"，结论才干净

### 4.3 评估方式

- `StratifiedKFold(n_splits=5, shuffle=True, random_state=42)` 交叉验证
- 输出 `classification_report` 与混淆矩阵
- 附加：`precision_recall_curve` 画 P-R 曲线，**用数据挑阈值**，而不是继续拍脑袋调 0.2 / 0.8

## 五、教学点（对应"ML / numpy / pytorch 学得浅"）

| 主题 | 具体动作 |
|---|---|
| numpy | 不用 sklearn，先用 numpy 手算混淆矩阵、精确率、召回率、F1，再与 `classification_report` 对照 |
| 特征工程 | 打印 TF-IDF 矩阵的 shape、词汇表大小、稀疏度，理解"文本如何变成数字" |
| 模型可解释性 | 打印逻辑回归系数最大的 20 个词 / 最小的 20 个词 —— 直接读出"哪些词最负面" |
| 类别不平衡 | 对比 `class_weight=None` 与 `"balanced"` 对负面召回的影响 |
| 阈值调优 | 用 P-R 曲线说明"阈值是业务决策，不是超参数"，并解释为什么 0.2/0.8 是拍出来的 |
| 交叉验证 | 理解为什么不能只报一次 train/test 的结果 |
| 采样偏差 | 亲手量化"分层抽样导致 accuracy 虚高"这件事 |

## 七、编码陷阱（今天已经踩过）

WPS 保存过的 CSV 会从 `utf-8-sig` 变成 ANSI(GBK)：

```python
pd.read_csv(path, encoding="gb18030")     # WPS 改过的文件
pd.read_csv(path, encoding="utf-8-sig")   # 脚本自己导出的文件
```

**判断方法**：用 utf-8 读时"中文乱码但数字正常" → 就是 GBK。
