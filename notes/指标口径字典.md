# 指标口径字典

> 项目：电商数据仓库简单实现项目
> 生成日期：2026-09-23　|　最近更新：2026-09-28（face 入口清洗落地、SnowNLP 阈值定档 [0.2,0.8]）　|　所属阶段：Phase 5
> 覆盖范围：PowerBI 看板 5 个 KPI + 4 张图、Python 分析 4 张图（图14/15/17/18）
> 用途：**每个指标"到底怎么算"的唯一权威定义**。改 SQL / DAX 前先查本表，看这一改会波及哪些指标；被问"这个数字怎么来的"时，翻对应条目即可回答，不靠回忆。

---

## 一、怎么用这份字典

| 场景 | 查哪一列 |
|---|---|
| 两个工具算出的数不一样 | **分子 / 分母 / 过滤条件** 三列并排看，通常立刻发现口径不一致 |
| 图表不随某个切片器变化，怀疑是 bug | **是否受切片器影响** 列，判断是设计还是故障 |
| 想换个工具复算这个指标 | **验证方式** 列，看它能不能被独立复算 |
| 样本太小占比不稳 | **最小样本量** 列 |

**排查顺序永远是：① 口径 → ② 数据 → ③ 代码。** 经验上 90% 的"数据不一致"其实是口径不一致。

## 三、逐条口径详情

### 1. 该职业总用户数（KPI 卡1）
- **业务定义**：当前筛选范围内，画像表里的全体用户数（含从未购买者）
- **分子**：`COUNT(dim_user_profile.user_id)`
- **分母**：无（计数类）
- **过滤条件**：无。切片器筛选由 PowerBI 筛选上下文注入
- **来源表.字段**：`dim_user_profile.user_id`
- **PowerBI 实现**：DAX 度量值 `该职业总人数 = DISTINCTCOUNT(dim_user_profile[user_id])`
- **最小样本量**：—
- **是否受切片器影响**：受「职业」切片器影响（face 就在维表上，直接筛选）；**不受「客户分群」切片器影响**（分群在 `*` 侧事实表，1→\* 单向关系流不回维表）
- **验证方式**：✅ Excel 交叉验证 —— `=COUNTA(明细!$B$2:$B$20000)` → **10,739**，差异 0
- **对应交付物**：PowerBI KPI 卡1

### 2. 购买用户数（KPI 卡2）
- **业务定义**：当前筛选范围内，有过购买行为的用户数
- **分子**：`COUNT(DISTINCT ads_rfm_segments.user_id)`
- **分母**：无（计数类）
- **过滤条件**：隐含"有购买行为"（`ads_rfm_segments` 建表时已 `HAVING f_freq > 0` 过滤）
- **来源表.字段**：`ads_rfm_segments.user_id`
- **PowerBI 实现**：DAX 度量值 `购买用户数 = DISTINCTCOUNT(ads_rfm_segments[user_id])`
- **最小样本量**：—
- **是否受切片器影响**：受「职业」切片器影响（1→\* 可传播）；受「客户分群」切片器影响（同表）
- **验证方式**：✅ Excel 交叉验证 —— `=COUNT(明细!$C$2:$C$20000)` → **6,110**，差异 0。原理：`COUNT` 只数数值，未购买者的 `r_days` 在 `LEFT JOIN` 后为空，天然被排除
- **对应交付物**：PowerBI KPI 卡2

> ⚠️ 与指标 1 的差别是**本项目的分母陷阱源头**：这个数读事实表（6,110），指标 1 读维表（10,739）。

### 3. 购买总额（KPI 卡3）
- **业务定义**：当前筛选范围内，所有用户的购买金额合计
- **分子**：`SUM(ads_rfm_segments.m_amount)`
- **分母**：无（求和类）
- **过滤条件**：无额外过滤（未购买者 `m_amount` 为空，`SUM` 自动跳过）
- **来源表.字段**：`ads_rfm_segments.m_amount`（= `dws_user_day.buy_amount` 的按人二级汇总，两级聚合后总和不变）
- **PowerBI 实现**：DAX 度量值（`SUM`）
- **最小样本量**：—
- **是否受切片器影响**：受「职业」与「客户分群」切片器**均影响**
- **验证方式**：✅ Excel 交叉验证 —— `=SUM(明细!$E$2:$E$20000)` → **1,805,829.50**，`|Δ| < 0.01`（`DECIMAL(14,2)` 舍入）
- **对应交付物**：PowerBI KPI 卡3

### 4. 平均单价（KPI 卡4）
- **业务定义**：当前筛选范围内，购买用户的人均购买金额
- **分子**：指标 3 购买总额
- **分母**：指标 2 购买用户数
- **过滤条件**：无
- **来源表.字段**：`ads_rfm_segments.m_amount` / `ads_rfm_segments.user_id`
- **PowerBI 实现**：`DIVIDE([购买总额], [购买用户数])`
- **最小样本量**：—
- **是否受切片器影响**：受两个切片器**均影响**（分子分母同源同向）
- **验证方式**：✅ Excel 交叉验证 —— `=B4/B3` → **295.55**，`|Δ| ≤ 0.01`
- **对应交付物**：PowerBI KPI 卡4

> ⚠️ 注意分母是**购买用户**不是全体用户。若误用 10,739 → 168.16，口径错误。

### 5. 高价值用户占比
- **业务定义**：当前筛选范围内，RFM 四类"重要"客户占**全体用户**的比例
- **分子**：`DISTINCTCOUNT(ads_rfm_segments.user_id)` 且 `user_segment IN ('重要价值客户','重要发展客户','重要保持客户','重要挽留客户')`
- **分母**：指标 1 该职业总用户数（**含未购买者**）
- **过滤条件**：无
- **来源表.字段**：`ads_rfm_segments.user_segment` / `dim_user_profile.user_id`
- **PowerBI 实现**：DAX 度量值 `高价值用户占比 = DIVIDE(CALCULATE(DISTINCTCOUNT(ads_rfm_segments[user_id]), ads_rfm_segments[user_segment] IN {...4类}), DISTINCTCOUNT(dim_user_profile[user_id]))`
- **最小样本量**：—
- **是否受切片器影响**：受「职业」切片器影响；**不受「客户分群」切片器影响**（分子里 `CALCULATE` 点名了 `user_segment` 列，为**替换语义**，会顶掉切片器在同一列上的筛选）
- **验证方式**：✅ Excel 交叉验证 —— 4 个 `COUNTIF` 相加 `/B2` → **28.44%**，`|Δ| ≤ 0.01`
- **对应交付物**：PowerBI KPI 卡5

> ⚠️ 本项目最容易写错的一处：分母若误用购买用户 → 3,054 / 6,110 = **49.98%**。数值"更好看"但口径错误。

### 6. 图11 RFM 八类客户分布
- **业务定义**：购买用户按 RFM 打分为 8 类后的各群人数与占比
- **分子**：`COUNT(*)`，按 `user_segment` 分组
- **分母**：**购买用户数 6,110**（不是全体用户 10,739 —— RFM 只对购买者有效）
- **过滤条件**：无（建表时已只保留购买用户）
- **来源表.字段**：`ads_rfm_segments.user_segment`
- **最小样本量**：—
- **是否受切片器影响**：受「客户分群」切片器影响（本身即该维度）；受「职业」切片器影响（1→\* 传播）
- **验证方式**：✅ Excel 交叉验证 —— 8 行 `COUNTIF(明细!$I列, 分群名)`，末行 `SUM` 自检 = **6,110**
- **期望值**：重要价值 1,588 / 重要保持 768 / 重要挽留 520 / 重要发展 178 / 一般价值 467 / 一般保持 231 / 一般挽留 1,537 / 一般发展 821（合计 6,110）
- **对应交付物**：图11 PNG + PowerBI 视觉对象

### 9. 图16 评论高频词 Top20
- **业务定义**：清洗后评论经分词、去停用词后，出现次数最高的 20 个词
- **分子**：各词在分词结果中的出现次数（`collections.Counter` 累加）
- **分母**：无（词频计数）
- **过滤条件**：`len(word) >= 2`、不在 `STOPWORDS`（5 轮迭代共 60+ 词）、非纯数字
- **来源表.字段**：`ods_comment.comment`（经 jieba 分词，加载 20 个电商自定义词）
- **最小样本量**：—
- **是否受切片器影响**：**不受任何切片器影响**（PowerBI 中该图为独立导入的 CSV 表，与模型无关系）
- **验证方式**：❌ **原理上不可用 Excel 交叉验证** —— 计算链依赖 `jieba 分词 + 自定义词典 + 停用词规则`，Excel 无分词能力，`SUBSTITUTE`/`LEN` 只能数"整串出现次数"，与 token 计数口径不同
  - 替代验证：① Python 重跑一致性（同源，弱验证）；② 人工抽查 Top10 词在原文中的实际出现次数；③ `SUBSTITUTE`/`LEN` 数整串做量级校验（预期 Excel 值 ≥ Python 值）
- **期望值（Top10）**：不错 2,614 / 喜欢 1,138 / 手机 1,084 / 包装 888 / 不好 668 / 屏幕 668 / 味道 654 / 华为 648 / 支持 639 / 速度 633（Top20 末位：水果 537）
- **对应交付物**：图16 PNG + `图16_评论高频词Top20.csv` + PowerBI 视觉对象

### 11. 图15 评论情感分布
- **业务定义**：清洗后评论按 SnowNLP 情感分数三分法（负面 <0.2 / 中性 0.2~0.8 / 正面 >0.8）的条数

## 四、通用口径约定

### 4.1 两人群层级（本项目最高危）
| 人群 | 来源表 | 人数 | 用于 |
|---|---|---|---|
| 全体用户（注册/画像） | `dim_user_profile` | 10,739 | 高价值占比、图13 的分母 |
| 购买用户 | `ads_rfm_segments` | 6,110 | 图11 占比、平均单价的分母 |

**规则：分母不同的两个占比，绝不能互相比较。**

### 4.2 核对判据（不同类型指标容忍度不同）
| 指标类型 | 允许差异 | 原因 |
|---|---|---|
| 计数类（人数、行数、分组数） | **必须 = 0** | 整数运算无误差 |
| 金额类（购买总额） | `|Δ| < 0.01` | `DECIMAL(14,2)` 舍入 |
| 均值 / 占比类 | `|Δ| ≤ 0.01` | Python `round(2)` 与 Excel `ROUND` 边界差 |

### 4.3 Excel ↔ SQL 等价映射
| SQL | Excel |
|---|---|
| `GROUP BY col` | 透视表 → 行标签 = col |
| `COUNT(*)` / `AVG()` | 值区域 = 计数项 / 平均值项 |
| `WHERE` | 筛选器区域 / 切片器 |
| `HAVING COUNT(*) >= 100` | **值筛选 → 大于等于 100** |
| `COUNT(DISTINCT)` | 透视表的"非重复计数" |

### 4.4 验证边界（不是所有指标都能交叉验证）
判断标准：**该指标的计算是否依赖某个无法在目标工具里复现的领域规则**。
- 纯聚合（计数/求和/平均/占比）→ 任何工具可重算 → 可交叉验证
- 依赖**领域词典 / 模型**（jieba 分词、停用词、SnowNLP）→ 只有具备该能力的工具能算 → **不可交叉验证**，必须显式标注 + 给出替代验证方式
